# What I recommend instead

I think there are **three phases left**, and they are different from the original roadmap.

---

# Phase A — Finish Component Extraction (before touching Dashboard)

We already extracted:

✅ Recruiter Navigation

✅ Recruiter Tabs

✅ Preselection

✅ Candidate Ranking

✅ Golden Badge

But we still need to create (or finish) these reusable recruiter pages:

```text
CVDirectory.tsx

QuizResults.tsx

OralPresentationResults.tsx

PreselectedCandidates.tsx
```

These should live in:

```text
src/components/recruiter/
```

Once these exist, the dashboard simply imports them.

---

# Phase B — API Connection

Replace mock data with API calls.

For example:

Instead of:

```ts
const aiCandidates = [...]
```

use

```ts
const candidates = await api.getCandidates();
```

Instead of local state for preselection, use your backend endpoints.

This phase connects the UI to the backend but **still doesn't require restructuring `Dashboard.tsx`**.

---

# Phase C — Dashboard Refactor (last step)

Only after everything above is ready do we update `Dashboard.tsx`.

The goal is to simplify it from something like:

```text
Dashboard.tsx
├── Sidebar
├── AI Filter
├── Quiz
├── Oral Presentation
├── Candidate List
├── Billing
├── Settings
├── ...
```

to:

```text
Dashboard.tsx
├── RecruiterNavigation
├── DashboardHome
├── CandidateList
├── CVDirectory
├── QuizResults
├── OralPresentationResults
├── PreselectedCandidates
├── Settings
├── Billing
└── ...
```

Notice the difference:

* **Today:** `Dashboard.tsx` contains all the logic.
* **Target:** `Dashboard.tsx` only decides **which component to render** based on `activeTab`.
